    XSKILL: Continual Learning from Experience and Skills in Multimodal Agents

    论文信息：Guanyu Jiang, Zhaochen Su, Xiaoye Qu, Yi R. (May) Fung （香港科技大学 / 浙江大学 / 华中科技大学），arXiv:2603.12056v3 (2026.07)。 论文原文 | 项目页 | 代码 提出 XSKILL——多模态智能体的双流持续学习框架，将"经验（action 级）+ 技能 （task 级）"两种互补知识锚定在视觉观测上做提取与检索，无参数更新地不断积累、 复用并持续改进。

    图片占位符：论文 Figure 1，同一多模态任务上有/无 XSKILL 的推理轨迹对比—— 基线因视觉语义鸿沟失败（未修正倒置图像、未放大小物体），XSKILL 召回相关经验并 链接到结构化技能片段，经上下文自适应生成"旋转 + 裁剪"的执行计划而成功。

    1. 摘要 (Abstract)

    • 核心问题：多模态智能体可调用多样工具做复杂推理，但仍存在工具使用低效 与工具编排僵化两大瓶颈；关键在于如何不更新参数、仅从过去轨迹中持续学习。
    • 两种互补的可复用知识：
    • 经验 (Experiences)：精炼的 action 级指导，用于工具选择与决策（战术知识）。
    • 技能 (Skills)：结构化的 task 级指导，用于规划与工具编排（工作流）。
    • XSKILL 方案：
    • 积累阶段：从多路 rollout 中经视觉锚定摘要 (Visually Grounded Summarization) 与跨 rollout 批判 (Cross-Rollout Critique) 蒸馏、整合出经验与技能。
    • 推理阶段：按当前视觉上下文检索并改写适配知识，并把使用历史反馈回积累 形成持续学习闭环。
    • 效果：在 5 个基准 × 4 个 backbone 上一致且显著优于仅工具与基于学习的基线， 较 tool-only 平均提升 Average@4 2.58–6.71 点，最强者最高达 11.13 点； 两知识流在影响推理行为上互补，且具备强零样本泛化。

    2. 引言 (Introduction)

    • 背景：MLLM 使智能体从被动感知走向主动求解，可集成视觉感知、代码执行、信息检索 等能力，但开放场景下仍有两个瓶颈：
    • 工具使用低效：简单问题浪费过多步骤，复杂查询又缺乏足够深的多轮探索 → 结构化 skill 可提供可复用工作流与工具模板。
    • 工具编排僵化：多数系统局限于单路径执行、难以跨任务泛化地组合工具 → 上下文敏感的 experience 可提供自适应工具选择的战术知识。
    • 类比人类：人类通过"经验 + 技能"两种途径持续改进解题能力——经验细化局部决策 （工具选择、探索、错误恢复），技能编码跨相关任务的高层规划与编排。
    • 现有工作的缺陷：多模态智能体的持续学习几乎空白；更重要的是，现有方法在知识 提取与检索时过度依赖纯文本轨迹日志，而多模态场景的关键决策信号常锚定在视觉 观测中——不把知识锚定在任务的视觉状态上，就难以可靠检索并适配先验知识。 少数相关工作（空间推理、GUI 导航）也只限于专门问题，缺乏通用方案。

    3. 方法论 (Method) —— 核心章节

    3.1 双流知识表征 (Dual-Stream Representation)

    • 技能 (Skill) \(k\in K\)：task 级指导文档，为一类问题提供结构化工作流。形式化为 \(k=(M,W,P)\)：\(M\) 为元数据（名称、描述、版本），\(W\) 为工作流序列， \(P\) 为可复用工具模板。以结构化 Markdown 文档存储。
    • 经验 (Experience) \(e\in E\)：非参数战术提示，捕获高层指令常省略的 action 级 洞察。形式化为 \(e=(c,a,v_e)\)：\(c\) 为触发条件，\(a\) 为推荐动作， \(v_e\) 为检索用语义嵌入；长度约束 \(|c|+|a|\le L^e_{\max}\)，桥接通用工作流与具体环境约束。
    • 问题建模 (POMDP)：任务 \(T=(q,I)\)（查询 + 图像集），工具集 \(\mathcal{F}\)， 目标是构造外部知识库 \(KB=(K,E)\)，使 \(\max_{KB} P[\hat y = y^* \mid T, KB]\)。视觉观测只提供任务状态的部分信息 （图像可见外观却未必能判断身份或所需上下文），故建模为部分可观测马尔可夫过程。
    • 双 MLLM 分工：MLLM_exec 负责工具使用推理，MLLM_kb 负责知识库操作 （提取、整合、适配）——可用更强模型做知识管理、执行模型保持灵活，且天然支持 跨模型知识迁移（一个模型积累的知识惠及另一模型）。

    3.2 Phase I：知识积累 (Accumulation)

    对训练任务 \(T_i\)，MLLM_exec 执行 \(N\) 条独立 rollout 得轨迹集 \(R_i\)，随后三步：

    (A) Rollout 摘要 (Visually Grounded Rollout Summary)：MLLM_kb 对轨迹、任务图像、 查询、真值及已适配技能做视觉锚定摘要，产出轨迹摘要 \(S_{R_i}\) 与技能片段 \(\Delta K_i\)。关键：把交错图像观测与轨迹文本联合分析，记录"做了什么动作"之外的 "何种视觉证据驱动了它、如何影响后续决策"（如倒置图像触发旋转、低对比度触发增强）。 技能提取包括工作流提取（结构化序列）与工具模板提取（可复用代码模式）， 具体实体替换为变量占位符以保证跨任务泛化。

    (B) 跨 rollout 批判 (Cross-Rollout Critique)：对成功/失败轨迹做对比分析， 识别结果背后的因果因素，产出结构化经验更新 \(\Delta E_i=\{op\}\)，每个操作为 \((\text{action},\text{args})\)，\(\text{action}\in\{\text{add},\text{modify}\}\)； 每条经验限长且要求可跨同类问题泛化。

    (C) 知识整合 (Hierarchical Consolidation)：把瞬时轨迹洞察转化为持久、可泛化的智慧： - 经验整合：(add,e) 前先查与既有条目余弦相似度 \(>\theta_{\text{sim}}\) 者， 若有则由 MLLM_kb 合并为单条保留核心洞察、删除原条目；(modify,e_{id},e') 就地更新； 超过容量 \(N^E_{\max}\) 时经验管理器按泛化性/可操作性删除冗余或低质条目。 - 技能整合：\(\Delta K_i\) 片段并入全局技能文档 \(K\)，MLLM_kb 逐节决定 更新/合并/删除；文档超长 \(L^K_{\max}\) 时触发精炼，以自评估检查各组件泛化性、 工作流正确性与简洁性，移除过度特化细节、用占位符替换具体实例。

    图片占位符：论文 Figure 2，XSKILL 框架总览——Phase I 左（多路轨迹经 Rollout Summary → Cross-Rollout Critique → 层级整合，产出 Markdown 技能文档与 JSON 经验条目， 由 Experience/Skill Manager 管理），Phase II 右（任务分解检索 → 上下文适配 → 注入 系统提示执行）。

    3.3 Phase II：用经验与技能解题 (Inference)

    (C) 任务分解检索 (Task Decomposition Retrieval)：直接用原始查询 \(q\) 检索会因视觉 语义鸿沟与查询特异性而次优。故由 MLLM_kb 把任务分解为 \(n_g\) 个抽象子任务 \(G=\{g_1,\dots,g_{n_g}\}\)（如暗图处理、几何比较、错误恢复），每个子任务生成短查询并按 嵌入检索 top-\(k\) 经验：\(E_{\text{ret}}=\bigcup_{g\in G}\text{Top-}k(\{e\in E\mid \cos(v_g,v_e)>\tau_{\min}\})\)。多面分解 + 子任务查询显著提升覆盖度。

    (D) 任务适配与注入 (Task Adaptation & Injection)： - 经验改写 (Experience Rewrite)：检索到的经验是通用的，可能含与当前任务无关的 细节；重写器按当前任务与视觉状态改写条件、用任务相关细节实例化动作、丢弃明显不适用 条目，得到 \(E_{\text{rewritten}}\)（如"规范图像方向"改写为"检测前先旋转倒置图像"）。 - 技能适配 (Skill Adaptation)：全局技能文档可能过细；适配器按当前图像与任务描述 剪掉无关章节、把改写经验并入工作流步骤、调整代码模板，得 \(K_{\text{adapted}}\)。 - 适配后的技能以非规定性参考注入系统提示（保留智能体临场发挥的空间）；执行时记录 实际使用的技能与经验形成使用历史 \(H_{\text{usage}}\)，反馈回积累阶段，使知识库 随真实使用模式持续精炼。

    4. 实验 (Experiments)

    4.1 设置 (Settings)

    • 基准（5 个 / 3 类领域）：
    • 视觉 Agentic 工具使用：VisualToolBench、TIR-Bench（视觉推理 + 多工具操作）。
    • 多模态搜索：MMSearch-Plus、MMBrowseComp（异构图文检索与浏览）。
    • 综合：AgentVista（工具 + 复杂搜索的极限挑战）。
    • 每基准随机抽 100 任务作积累训练集、其余作测试；MMBrowseComp（仅 130 条） 全部作测试，充当 OOD 迁移目标。
    • 基线：无工具 / 仅工具 (w/ Tools)，以及学习式方法 Agent Workflow Memory (AWM)、 Dynamic CheatSheet (DC)、Agent-KB；所有方法在同一训练集上积累经验、推理时检索。
    • Backbone：Gemini-2.5-Pro、Gemini-3-Flash、GPT-5-mini、o4-mini；开源的 Qwen3-VL-235B/32B（附录 A）。Gemini 系积累自身知识；GPT-5-mini / o4-mini 直接使用 Gemini-3-Flash 积累的知识检验跨模型迁移。
    • 工具：代码解释器、网页搜索、图像搜索、访问网页。
    • 指标：成功率；\(N=4\) 次 rollout 下报告 Average@4（平均成功率，稳健性）与 Pass@4（至少一次成功比例，上界能力）。检索 top-k=3，温度 0.6，最多 20 轮。

    4.2 主要结果 (Main Results)

    • 总览（Table 2）：XSKILL 较 tool-only 在四个模型上 Average@4 提升 2.58–6.71 点；且多为最强基线之上最一致的胜者。Pass@4 同样一致提升——既提升单条 rollout 的 可靠性，也提升整体上界能力。
    • 典型：TIR-Bench / Gemini-3-Flash 上 Average@4 达 47.75%，超过最强基线 Agent-KB 11.13 点——双流设计有效捕获复杂视觉推理 + 多步工具组合所需知识。
    • 跨模型迁移：GPT-5-mini、o4-mini 用 Gemini-3-Flash 积累的知识，较 tool-only 提升 2.58–4.16 点——外化知识无需逐模型积累即可跨架构生效。

    4.3 消融实验 (Ablation, VisualToolBench / Gemini-2.5-Pro)

    变体 Average@4 Pass@4 ΔAvg@4
    Full Pipeline 30.49 46.73 –
    w/o Experience 27.45 42.52 -3.04
    w/o Skill 26.64 41.12 -3.85
    w/o Experience Manager 26.40 42.06 -4.09
    w/o Skill Manager 26.87 42.99 -3.62
    w/o Task Decomposition 29.21 44.86 -1.28
    w/o Task Adaptation 28.97 44.39 -1.52
    w/ Tools（无知识） 25.35 40.65 -5.14
    • 两类知识都必要：去掉经验或技能各降 3.04 / 3.85 点。
    • Phase 1（知识质量）> Phase 2（检索机制）：去掉 Experience/Skill Manager 各降 4.09 / 3.62，而去掉任务分解/适配只降 1.28 / 1.52 → 积累知识的质量比检索机制更关键， 但两阶段对最优性能都不可或缺。

    4.4 行为分析与泛化 (Analysis)

    • 技能缓解工具使用低效：从仅经验到仅技能，执行错误率从 29.9%（168 次）降至 15.3%（95 次）；结构错误显著减少——语法错误 114 (20.3%) → 71 (11.4%)，工具名错误 16 → 2。清晰的工具模板与工作流让智能体不再把有限轮次浪费在错误恢复上。
    • 经验带来灵活编排：引入经验后工具使用分布明显偏移——VisualToolBench 上代码解释器 使用 66.63% → 74.49%（仅经验）/ 76.97%（完整管线）；MMSearch-Plus 上代码解释器 6.18% → 13.21%、图像搜索 15.43% → 24.63%。经验捕获"针对具体任务的战术知识"， 突破基线的固定执行路径。
    • rollout 数量的影响：\(N\in\{1,2,3,4\}\) 下性能单调提升、Pass@4 增益更陡—— 更多 rollout 提供更丰富的轨迹多样性，让跨 rollout 批判提炼出更高质量的经验、 归纳出更泛化的技能。
    • 跨任务零样本迁移：VisualToolBench 知识 → TIR-Bench、MMSearch-Plus 知识 → MMBrowseComp，在所有模型与基准上优于全部基线，较 Agent-KB 平均 +2–3 点——源于 层级整合（去场景化细节、保通用洞察）与任务适配（按当前任务定制）。
    • 开源模型迁移（附录 A.1）：把 Gemini-3-Flash 的知识迁给 Qwen3-VL 235B/32B 效果 混合——MMSearch-Plus 有增益，但 VisualToolBench 的 Average@4 为负（外部知识干扰 较弱模型的原生工具行为）；不过因探索增加（工具调用次数↑）Pass@4 仍上升 → 基础模型能力足够强是知识有效迁移的前提。

    图片占位符：论文 Figure 3，VisualToolBench 错误分析（技能显著减少语法/运行时 错误）；Figure 4，不同 rollout 数量下的性能；Figure 5，OOD 迁移性能对比。

    5. 相关工作 (Related Work)

    • 多模态 Agentic 推理：MLLM 已从静态视觉理解转向主动"用图像思考"，现有框架却基本 无状态——单集孤立运行，无法跨任务内化成功工具模式或纠错反馈，导致重复试错； 参数化 RL 方法受高训练成本与工具集演化困难制约 → 需要非参数化的持续积累机制。
    • 从经验与技能中学习：早期方法检索原始轨迹，近期转向抽象为可复用知识——经验 （条件-动作战术洞察）与技能（高层工作流 + 可复用模板），EvolveR / ReasoningBank 等 引入闭环演化。但多模态场景下的经验学习几乎未被探索：现有多模态记忆工作局限于 GUI 导航 / 空间推理等专门任务，检索时依赖原始文本指令、缺乏锚定视觉上下文的 "先规划再检索"，也不对检索到的经验/工具模板做适配。XSKILL 以视觉锚定提取 + 上下文 感知适配填补该空白。

    6. 结论 (Conclusion) 与讨论

    • XSKILL 统一 task 级技能与 action 级经验：视觉锚定提取 + 层级整合支撑积累， 视觉锚定检索与适配桥接知识与任务需求；技能保证工具执行稳健性，经验引导基于 任务上下文的策略选择，两流互补。强零样本迁移说明学到的是可泛化推理原则而非简单 启发式。
    • 当前实验是单轮"积累-测试"循环，但架构支持随新任务持续迭代精炼。
    • 社会影响：外化知识可被审计、编辑或删除，提升可解释性；但更强智能体可能被恶意 自动化滥用、或经积累循环继承并放大轨迹中的偏见——且跨模型迁移意味着一个模型积累的 偏见可能无附加防护地扩散到其他模型 → 建议人工复核知识库、周期性偏见审计、对跨模型 知识迁移做访问控制。
    • 局限：强 backbone 上效果最佳，弱/开源模型上迁移增益有限（依赖基础模型能力）； 知识质量仍取决于积累阶段的监督来源。

    7. 一句话总结

    XSKILL 用"技能（任务级工作流）+ 经验（动作级战术）"双流知识，全程锚定在视觉观测 上做提取、检索与适配（Why：多模态的决策信号在图像里，纯文本轨迹抓不住）， 无参数更新地让多模态智能体持续积累与改进工具使用。
