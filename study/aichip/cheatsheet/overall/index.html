    Overall

    1. 通用性能公式

    Execution time：单指令 CPI × clock cycle time；程序 T = IC × CPI_avg × T_clk。多周期 CPU：CPI_avg = Σ f_i × cycles_i。若有 cache miss：T = T_base + (#memory accesses) × miss rate × miss penalty。

    Amdahl 定律：若可并行比例为 f，处理器数 N，Speedup = 1 / ((1-f)+f/N)；上限 1/(1-f)。并行部分不是免费：同步、负载不均、资源争用都会降低收益。

    Little 定律：L = λW。硬件里常写：concurrency/buffer size = throughput × latency。例：12GB/s、100ns → 约 1200B? 注意单位：12×10^9 B/s ×100×10^-9s=1200B

    Roofline：AI = total OPs(or FLOPs) / memory bytes；attainable throughput = min(peak compute, AI × peak bandwidth)。拐点/ridge point：AI* = peak compute / peak bandwidth。AI < AI* memory-bound；AI > AI* compute-bound。优化判断：实测点接近 roofline → 已接近充分优化；离 roofline 很远 → 算子实现、并行度、访存、向量化仍有问题。

    AMAT：AMAT = hit time + miss rate × miss penalty。若题目说 miss access time 已包含 hit time，则用 hit_rate×hit_time + miss_rate×miss_time；没说明通常按前者。

    2. Von Neumann / 单周期 / 多周期 / 流水线

    Von Neumann 两点：stored program（指令和数据存于统一线性内存）；sequential instruction processing（in-order commitment）。

    Single-cycle：CPI=1，但 T_clk 由最慢指令决定。没有程序员不可见中间状态。

    Multi-cycle：把指令分成若干状态，一条指令多周期，T_clk 变短；不同指令周期数不同。ISA 只规定 AS→AS'，微结构可加入不可见状态 MS。

    Pipeline：把指令处理分为 IF/ID/EX/MEM/WB 等阶段，不同指令占不同阶段。稳态理想 CPI≈1，提升 throughput 而非单条 latency。总周期粗略：k + n - 1 + stalls（k 为阶段数）。

    Hazard：结构冒险（硬件资源冲突）、数据冒险、控制冒险。数据依赖：RAW 真依赖必须遵守；WAR/WAW 是名称依赖，可用 renaming 消除。Forwarding/bypass 可减少 RAW stall；load-use 常仍需等待；branch 需要预测/flush。

    3. 数据依赖与寄存器重命名

    WAR/WAW 本质是 architectural register 名字不够，不是值依赖。

    Renaming 核心：把 architectural register 映射到 physical register / ROB entry / RS tag。后续消费者不再看“R3”，而是看“产生当前 R3 新值的 tag”。这样同名但无关的值被拆开。

    4. ROB（Reorder Buffer）

    目的：out-of-order complete，但 in-order commit，保证 precise exception。异常发生时，已 commit 的都是老指令，新指令可 flush。

    ROB 流程： 1. in-order Decode/rename 按程序顺序分配 ROB entry，目的寄存器 rename 到该 entry。 2. OoO Execute: 可乱序完成，结果先写 ROB，不直接写 architectural state。 3. In-order Commit 只检查 ROB head。若 head ready 且无异常，写回寄存器/内存；若异常，flush 后跳异常处理。

    ROB 可存字段：busy/valid、dest architectural reg、value、ready、exception、PC/order。Load/store 常还需地址/数据/是否可提交。

    为什么 precise exception 需要 in-order commit：如果新指令先把结果写入寄存器/内存，老指令再异常，体系结构状态无法恢复到“异常指令之前”的顺序状态。

    5. Tomasula：三大结构与时间点（重点）

    Why OoO？

    • In-order 里，一条长延迟指令会把后面的独立指令也挡住。
    • OoO 让“数据已就绪”的指令先执行，提升吞吐。

    Tomasulo 三组件：Register Rename/Alias Table，Reservation Station，Common Data Bus(CDB)。现代处理器常再加 ROB 以保证 precise exception。

    5.1 Register Renaming Table / RF 表

    表项：Valid/V、Tag、Value。V=0寄存器的新值尚未产生，Tag 指向将产生它的 RS entry 或 ROB/physical reg。

    ID/rename 时更新： 1. 若有空 RS，指令占用一个 RS entry，记该 entry 的 tag。 2. 对每个源寄存器：若 RF/RAT 中 V=1，把 value 复制到 RS.source.value 并设 source.V=1；若 V=0，把 producer tag 复制到 RS.source.tag 并设 source.V=0。 3. 对目的寄存器：RF/RAT[dest].tag = 当前 RS tag，V=0。这一步就是 register renaming，可消除之后指令看到的 WAR/WAW。 4. 若无空 RS，则 issue/rename stall。

    CDB/WB 时更新：执行完成后，FU 申请 CDB，广播 (tag,value)。所有 RS 监听：若某 source.tag 匹配广播 tag，则写入 value 并把 source.V 置 1。RF/RAT 也监听：只有当 RF/RAT[reg].tag 仍等于广播 tag，才写 value 并置 V=1；若 tag 不匹配，说明该 architectural reg 已被更新指令重新 rename，不能覆盖。

    5.2 Reservation Station（RS）

    RS 是等待区/调度窗口。常见字段：Busy/Valid、Op、DestTag、src1/src2: V/Tag/Value可能还有 immediate、地址、ROB id。

    RS 的意义：把等待操作数的指令从流水线前端移开，让无关指令继续进入；每条指令在 RS 中等自己的源 tag/value。所有源 V=1 且 FU 可用时 wakeup/select/dispatch。执行顺序按 dataflow，不按原程序顺序。

    RS 更新规则： - 插入时填操作码、目的 tag、两个源的 value/tag。 - 等待时监听 CDB，匹配 tag 就抓值。 - ready 后发送到功能部件；执行完成并广播后，RS entry 释放。

    5.3 CDB（Common Data Bus）

    广播完成结果 (tag,value)；一个周期通常只能广播有限个结果，所以可能发生 CDB arbitration。CDB 同时唤醒消费者和更新 RF/RAT。

    6. Tomasula/OOO 题模板

    常见答案句：WAW hazard 例：I2 和 I4 都写 $s4。解决：register renaming，把两个 $s4 的不同版本映射到不同 ROB/RS/physical tag，commit 时保持程序顺序。

    填表小心：fully pipelined FU 表示可每周期启动新操作，但 latency 多周期；non-pipelined 才必须等整条操作结束。in-order commit/precise exception 表示新指令即使早完成，也只能在所有更老指令 commit 后 W。

    关键性能限制:

    • 指令窗口 = RS 中未发射 + ROB 中未提交的指令总数。越大，可发现的并行性越高，但硬件（CAM、仲裁）开销剧增。
    • 延迟容忍度：由窗口大小决定；若一条长延迟指令，需巨大窗口才能继续填充独立指令。

    7. Superscalar / SIMD / Multi-core

    Superscalar：一周期 fetch/decode/issue 多条指令，需要同周期依赖检测和多个功能部件。issue width 越大，issue queue、multi-port RF、bypass 网络复杂度快速上升，收益递减。多核优于超大单核：应用可并行、多程序负载多，单核 ILP 有限。

    Flynn 分类：SISD；SIMD（vector/array）；MISD 少见，近似 systolic/streaming；MIMD 多指令多数据（多核、多线程）。

    SIMD vs SIMT：SIMD 由程序显式写向量宽度；SIMT 用线程编程，硬件把一组线程组成 warp，warp 内执行同一指令。GPU 本质是用 SPMD 编程模型跑在 SIMD/SIMT 硬件上。

    Fine-grained Multithreading: 每周期切换到另一个线程，以确保同一线程中的两条指令不会同时进入指令流水线。无需指令间依赖检测、分支预测，提高吞吐量；但硬件开销大（多套线程上下文），单线程性能下降

    8. GPU 架构与优化

    CUDA 映射：Grid → (Thread)Blocks → Threads；硬件：GPU → SM → CUDA cores/SIMT lanes；warp 通常 32 consecutive threads，是基本调度单位。一个 thread block 可被调度到一个 SM；block 间顺序不保证。

    • SPMD（编程模型）：程序员编写一份源代码，运行在多个处理单元上，处理不同的数据（如CUDA Kernel）。
    • SIMD（硬件指令级并行）：一条指令直接控制多个数据通道（如CPU的AVX指令）。
    • SIMT（硬件架构模型）：是SPMD编程模型在SIMD硬件上的具体实现。将大量标量线程动态捆绑为固定大小的“线程束（Warp）”，将Warp内的线程一一映射到SIMD通道上。
    • 本质关系：SIMT牺牲了SIMD“全速无分支”的极致效率，换取了类似SPMD“易于编程、处理复杂分支”的灵活性，是一种权衡产物。

    如何优化global mem access: multithreading, memory coalescing, shared memory

    Latency hiding：GPU 用 fine-grained multithreading(FGMT) 在 long-latency memory 时切换 warp。Occupancy = active warps / max warps。occupancy 太低无法隐藏延迟；太高也可能受寄存器/shared memory 限制而不一定更快。

    Memory coalescing：同一 warp 连续线程访问连续/对齐地址 → 合并为少数 memory transaction；stride/随机访问导致 transaction 多，带宽浪费。

    Shared memory / tiling：把全局内存 tile 搬到 shared memory，__syncthreads() 后复用，减少 DRAM 访问。矩阵乘典型：加载 A_tile/B_tile，每个线程算一个/多个 C 元素。注意 bank conflict：多个线程访问同一 bank 不同地址会串行；padding 可缓解。

    GPU 优化关键词：coalesced global load/store；shared-memory tiling；减少 divergence；提高 arithmetic intensity；减少 register spilling；合适 block size；使用 warp-level primitive；避免非合并原子/随机访存。

    9. 存储层次与存储技术

    理想内存：零延迟、无限容量、无限带宽、零成本，但现实中 bigger/slower、faster/expensive、bandwidth/ports/banks expensive。

    层次：寄存器/FF 最快最贵；SRAM 用于 cache/shared memory/global buffer；DRAM/HBM 容量大但延迟高；SSD/disk 更慢更便宜。SRAM 适合片上缓冲，DRAM 优化更多面向容量/带宽而非延迟。

    DRAM子系统：Channel->DIMM->Rank->Chip-Bank->Row/Column; DRAM由于capacitor漏点需refresh，有耗能，降低性能和QoS

    DRAM row buffer：顺序访问 row-buffer hit 多，吞吐高；随机访问 row-buffer miss 多，ACTIVATE/PRECHARGE 开销大，吞吐差。

    10. Cache 基础

    局部性原理：temporal locality：最近访问很快再访问；spatial locality：相邻地址很快被访问。Cache 自动利用局部性；accelerator 常用 software-managed buffer/scratchpad 利用固定模式。

    地址分解：[tag | index | block offset]。offset bits = log2(block size)；#blocks B = capacity C / block size b；#sets S = B / associativity N；index bits = log2(S)；tag bits = address bits - index - offset。

    访问步骤：用 index 读 tag/data store；检查 valid；比较 tag；hit 则返回；miss 则按替换策略选 victim，把 memory block 调入，必要时写回 dirty victim。

    组织：direct-mapped：N=1,S=B，简单快但 conflict 多。fully associative：N=B,S=1，冲突少但比较器多。N-way set associative：1<N<B,S=B/N，折中。

    Replacement：invalid first；否则 Random/FIFO/LRU/PLRU/Hybrid。LRU 不总优：4-way cache 循环访问 A,B,C,D,E 会 0% hit（set thrashing），Random 可能更好。

    Block size 取舍：太小利用不了空间局部性、tag overhead 大；太大 block 数减少、可能浪费带宽和容量、时间局部性下降。

    多级缓存： - 一级缓存追求低延迟，容量小、低相联度，tag 与数据并行读取，设计受时钟周期限制； - 二级缓存侧重均衡命中率，大容量高相联度，延迟次要，tag 与数据可串行读取； - 多级串行访问模式下一级缓存过滤大部分访存，两级缓存访问流量、管理策略均不相同。

    11. Cache miss 分类与降低方法

    • Compulsory/cold miss：第一次访问该 block，任何 cache 都 miss；可用 prefetch 缓解。
    • Capacity miss：即使 fully associative 且同容量最优替换仍会 miss，因为工作集大于 cache。
    • Conflict miss：不是 compulsory，也不是 capacity，由映射冲突导致；增加 associativity、victim cache、更好 indexing、随机化、软件布局可缓解。

    12. Cache 写策略

    1. write miss 时：write-allocate（默认，先把整行读入 cache 再写）或 write-no-allocate（常用于 IO/streaming，直接写内存，不污染 cache）。

    2. write hit后：write-back（默认，只写 cache，evict dirty 时写内存）或 write-through（cache 和内存同时写）。

    3. Write-back：省带宽、合并多次写；需要 dirty bit，一致性复杂

    4. Write-through：简单、下层始终新、evict 不写回；但带宽开销大。
    5. I-cache/D-cache：L1 常 split（I/D 各自低延迟、避免结构冲突）；更高层常 unified（空间动态共享）。

    13. Cache Coherence（一致性）

    Coherence vs Consistency：coherence 关注同一 memory location/cache block 的多核访问顺序，是局部顺序；consistency 关注不同处理器对所有 memory operations 的全局可见顺序，是程序员-微结构契约。

    硬件组成：cores + private caches + interconnect + memory。Interconnect：snoop/bus 或 directory。更新策略：invalidate 或 update。

    Snooping/bus：所有 cache 监听总线命令，适合小规模；一次一个事务，可广播 invalidation/read miss。

    Directory：每个 block 有 home node 维护目录；local node 发请求，home node 转发给 remote/sharer/owner。可扩展到 many-core，避免全局广播。

    Directory 字段：state bits；owner id（log2N bits，拥有唯一 dirty/modified copy 的 cache）；sharer list（N-bit one-hot，记录哪些 core/cache 有该 block 的副本）。

    14. MSI / MESI 状态协议

    MSI：I invalid：本 cache 无该 block；S shared：一个或多个 cache 有 clean copy，只读；M modified：唯一 dirty copy，可本地读写，内存旧。Read miss 取数；write 需要 invalidate 其他副本；M 被别人读时需提供/写回并转 S。

    MESI 在 MSI 上加 E exclusive：唯一 clean copy。E 状态本地读/写无需 bus；本地写 E→M 不发 invalidate。远端读 E→S；远端写 E→I。

    15. Memory Consistency / Barrier

    Ordering：硬件为了性能会乱序执行/提交/可见，但程序员需要某种“约定顺序”。越强的 consistency model 越容易编程、越难高性能。

    四类 barrier：Load-Load/Load-Store/Store-Store/Store-Load(最昂贵)：前序访存操作不可重排至后序访存操作之后

    模型对比：Sequential Consistency 最强，四种 barrier 都保证；TSO(Total Store Order)（x86/64）通常允许 Store-Load 重排；PSO(ARM) 更弱；更弱模型性能更高但程序员需显式 fence/atomic。

    16. AI 加速器动机与原则

    DNN 特性：Conv/FC/Attention 主要是矩阵乘/MAC，计算量占比很高；访存模式较固定（Activation/FC: Burst; Conv/Pooling/Attention: Burst+Stride）；DRAM 访问能耗远高于 multiply。目标：提高 throughput、降低能耗（减少内存、buffer访问），可牺牲通用性。

    DSA 五原则： 1. Global Buffer/Scratchpad：用专用片上存储减少搬运距离，替代复杂 cache。 2. 简化控制：省掉复杂 OoO/预测/大 cache，把面积给计算阵列和片上存储。 3. 并行计算模块：直接支持矩阵/向量级操作。 4. 量化：FP16/BF16/INT8 等降低计算与带宽。 5. 专用编程语言/编译器/runtime：让软件显式管理数据搬运和调度。

    CPU vs DSA：CPU：cache、superscalar、inter-instruction parallelism、full functionality、低延迟、general language。DSA：global buffer、in-order/simple、intra-instruction parallelism、partial functionality、高吞吐、domain-specific language。

    Cache vs Buffer:buffer能耗低，面积小，手动管理

    AI加速器集中在推理而非训练：AI训练内存带宽往往是整体性能的瓶颈，AI加速器不能明显地提高内存带宽的利用效率。由于推理加速器能把模型存到AI芯片上，可提高10+倍能耗比；训练加速器不能把模型和中间结果都存到芯片上

    17. 矩阵乘单元 / Systolic Array / TPU

    C=A×B。Scalar: 16^3=4096 次；Vector 可并行一个维度；Matrix unit 一条指令/一拍完成 tile 乘，算力密度高但灵活性低。

    Systolic array：二维 PE 阵列，数据有节奏地在阵列中流动。PE 更新：Right = Left，Down = Upper，Cell += Upper × Left。优势：权重/激活/partial sum 在片上复用，减少 global buffer/DRAM 访问。周期数T=3N-2，N为方阵宽

    TPU v1：核心是 256×256 MAC systolic array + Unified Buffer；推理场景，模型可预存 DDR，输入经 PCIe 来。

    18. Ascend / DaVinci AICore

    Cube 模块（算力担当）：矩阵乘单元。FP16：一拍做 16×16 与 16×16 矩阵乘；INT8：16×32 与 32×16。Accumulator 做 C=A×B+C，支持卷积 bias/累加。L0A/L0B/L0C 分别存左矩阵、右矩阵、结果/中间结果；A/B DFF 和 Accum DFF 缓存当前 tile。

    Vector 模块（多面手）：支持 FP16/FP32 等向量运算，连续/固定间隔/VA 不规则寻址。UB 保存源/目的操作数，一般 32B 对齐。L0C→UB 搬运可经 Vector Unit 做 ReLU/格式转换。

    Scalar 模块（司令部）：像小 CPU，负责循环控制、分支、Cube/Vector/MTE 指令地址和参数计算。

    MTE（Memory Transfer Engine）：负责 Global Memory/UB/L0A 等之间的数据搬运与格式转换，如 padding、transpose。

    L2 Buffer vs L2 Cache：同一介质两种模式。Buffer 程序员可见、地址空间与 DDR/HBM 不重合；Cache 对程序员不可见，作为 DDR/HBM 高速缓存。

    19. CANN / MindSpore / 图优化

    CANN：介于 AI chip 和 AI framework 之间，提供计算加速库、芯片算子库。CUDA 对 NVIDIA，CANN 对 Ascend。

    算子开发：Tensor是存储算子输入数据与输出数据的容器，于Device memory中；TBE DSL：Python，高封装，适合简单算术逻辑/内置矩阵池化，入门低但复杂逻辑受限。TIK：Python，直接控制搬运和 schedule，适合复杂算子，性能潜力高但入门难。AI CPU：C++，用于 AI Core 不易实现或快速打通网络，但性能低。

    图优化：CSE 公共子表达式消除；算子融合把 Conv/BN/ReLU 等相邻算子合并，减少中间张量读写，提高局部性和带宽利用。MindSpore：自动并行、图算融合、内存优化、流水线执行、自动微分、类型推导、二阶优化等。

    20. Parallel Training 总览

    Backward 计算约为 forward 的 2×，且需要 forward activations，存在 RAW dependency。分布式训练动机：模型大、数据大、单卡内存有限，所以要scale-out。模型训练4组成：computing, storage, networking, compiling

    并行分类：Data Parallel；Model Parallel → Intra-layer/Tensor Parallel, Inter-layer/Pipeline Parallel；Hybrid Parallel。

    21. Data Parallel

    • 每张卡(worker)(共N张)有完整模型副本，切分训练数据。前向/反向：各卡独立计算，无需通信。
    • Fwd 和 Bwd
    • 权重更新：需对 N 张卡的梯度求平均（Summing 1/N gradients），通信原语为 AllReduce。
    • Ring AllReduce: 拓扑1D torus(ring)；每个 worker 只和两个邻居通信;两阶段：
    • Reduce-Scatter（N-1 steps）：每步每卡只负责汇总最终结果的 1/N 块。
    • AllGather（N-1 steps）：将汇总好的块广播给所有卡。
      • 共 2(N – 1) steps, worker sends/receives 1/N of all bytes
      • 每步都要同步 -> 2(N – 1) syncs total
    • 单卡(worker)通信量：
    • 每轮收发 = M / N 字节（M 为总数据量）。
    • 单卡总发送 = 单卡总接收 = 2(N-1) × (M/N)。
    • 单卡总吞吐（Tx+Rx） = 2M(N-1) / N ≈ 2M（当 N 较大时）。
    • 扩展性评价(增加卡数)：强扩展（固定总 Batch）：每卡 Batch 变小，BN 不准，显存利用率低。弱扩展（增大总 Batch）：需调整 LR、优化器，收敛至同样精度 Epoch 可能增加。
    • 优点：通信可与反向计算重叠（算完一层梯度即可同步该层）。

    22. Pipeline Parallel

    • 定义：按网络层切分，每张卡负责若干层。
    • 通信模式：点对点（P2P）传输激活值（前向）和激活梯度（反向）。
    • 一般流水线：(N-1)/N idle slots
    • gpipe: N workers, K subminibatches
      • 2(N + K – 1) steps for fwd/bwd
      • Total step-slots: 2N(N + K – 1)
      • Idle step-slots: 2N(N – 1)
      • 空闲率: (N – 1)/(N + K – 1)
      • K 越大，气泡占比越小；但当N增大时，需同比例增大K维持效率
    • 挑战：存在空闲气泡;各层计算负载难均衡（计算量不同）难与计算重叠（顺序依赖，等上游数据到达才能计算）

    23. Tensor Parallel

    • 定义：将单层内的权重矩阵按行或列切分到多卡
    • Row-wise：权重按行切分
      • Fwd: AllGather 拼凑输出; Bwd: ReduceScatter
      • 每卡算出部分行结果，需聚合；反向时梯度需按行散播累加。
    • Column-wise：权重按列切分
      • Fwd: ReduceScatter 累加部分和; Bwd: Allgather
      • 每卡算出的列结果需相加；反向时需将完整梯度广播回各列

    • 交替切分—— 减少通信的关键

      • 策略：第 K 层用行并行，第 K+1 层用列并行。
      • 通信优化逻辑：行并行的输出是按行切分的（Worker i 持有连续行区间）。列并行要求输入也按行切分（因为列切权重与输入行相乘是独立的）。
      • 结论：行并行 → 列并行，跨层通信为 0（无需 AllGather 或 ReduceScatter）。
      • 交替后的整体开销：
        • 若顺序为 行→列→行，则只有在列→行的边界需要做一次 AllReduce。
        • 对比无交替（每层都通信）：同步次数减半（减少 50%）。

    • 挑战：难与计算重叠

    • ZeRO（零冗余优化器）：将优化器状态（动量、方差）、梯度和模型参数切分到各卡，解决单卡显存不足。代价是增加了少量通信量。

    24. AllReduce / Ring AllReduce（重点）

    AllReduce：每个 worker 起始有长度 M 的向量，结束时每个 worker 都有全体 worker 的规约结果（sum/avg/max）。Data parallel 用于梯度平均；tensor parallel 也可能在交替 row/col 时用。

    考试常见判断：不是所有 worker 两两互发完整 M。worker 需要 CPU/GPU cycles 做规约，可能与计算重叠但也可能成为瓶颈。

    26. Roofline 例题答案模板

    题：Conv 10000 OP /1000B，5.8 TOP/s；FC 30000/1000B，7.9；Attention 50000/1000B，6.1。图中峰值 12 TOP/s，ridge AI=20 OP/B。

    计算：peak compute=12 TOP/s；bandwidth=12/20=0.6 TB/s=600 GB/s。AI：Conv=10，FC=30，Attention=50 OP/B。Roof 上限：Conv=min(12,10×0.6)=6 TOP/s；FC=12；Attention=12。

    放点：Conv (10,5.8) 接近 6，几乎 fully optimized，memory-bound。FC (30,7.9) 低于 12，不充分，compute-bound。Attention (50,6.1) 低于 12，不充分，compute-bound。若 Conv 另一实现只是让计算单元更快，吞吐不一定提高，因为 Conv 已 memory-bound；应优化访存/提高 AI/减少 bytes。

    27. Performance Analysis 例题答案模板

    题：clock=2ns；load 4cyc、store 6、arith 2、branch 3；mix=20/10/50/20%。

    (a) CPI=0.2×4+0.1×6+0.5×2+0.2×3=3.0。

    (b) miss penalty=100ns，hit time=1 cycle=2ns，miss rate=1.4%。AMAT=2+0.014×100=3.4ns（若题目把 miss time 当总 miss access，则 0.986×2+0.014×100≈3.372ns，写清假设）。

    (c) 100 instr，avg 1.3 mem access/instr。Base=100×3×2=600ns。Miss extra=100×1.3×0.014×100=182ns。Total≈782ns。

    (d) 2-way miss rate=1.0%，clock 增为 2×1.05=2.1ns。Base=100×3×2.1=630ns；miss extra=100×1.3×0.01×100=130ns；total=760ns。所以 2-way 更快（760ns < 782ns），虽然 clock 变慢，但 miss 降低收益更大。

    28. Cache 例题答案模板

    题：32B cache，block=4B，byte-addressable，序列 0x8,0x28,0x8,0x88,0x8,0x28。Block number=addr/4：2,10,2,34,2,10。

    Direct mapped：B=8，S=8，index=block mod 8，三者 index 都是 2。结果：M(C), M(C), M(conflict), M(C), M(conflict), M(conflict)，hit rate=0/6。第一次访问某 block 即 compulsory，即使同时造成替换也优先记 compulsory。

    2-way set associative：B=8，N=2，S=4，index=block mod 4，三者仍同 set=2，但 set 有 2 ways。LRU 过程：2 M；10 M；2 H；34 M evict 10；2 H；10 M(conflict)。hit rate=2/6。

    Fully associative：8 ways，三个 block 都能同时放下：2 M；10 M；2 H；34 M；2 H；10 H。hit rate=3/6。最高：fully associative。

    29. Pipelined/OOO CPU 例题做法压缩

    流水线表通用技巧：若有 RAW，消费者 E 起点 ≥ 生产者结果可用周期；若 FU fully pipelined，只限制 start rate；若 precise exception，W 必须严格按程序顺序。in-order dispatch 机器中，前面一条因 RAW 等待会挡住后面独立指令；OOO 用 RS 把等待指令移开。

    30. 考试易错点

    1. tag 不是值；valid=0 表示等 tag 对应的未来值。
    2. CDB 更新 RF 时必须检查当前 tag 是否仍匹配，避免旧 producer 覆盖新 rename。
    3. ROB 解决 precise exception；RS 解决等待/乱序调度；renaming 解决 WAR/WAW。
    4. Ring AllReduce 是 ReduceScatter + AllGather，不是单纯 all-to-all。
    5. Tensor parallel 的 row/column 通信按 PPT：row fwd Allgather，column fwd ReduceScatter；backward 相反；交替每两层 AllReduce。
    6. Cache miss 分类先看是否第一次访问 block；直接映射冲突多，fully associative 不一定现实最快。
    7. Coherence 是 same address/block；Consistency 是 all memory operations。
    8. Roofline 中实测点低于 roof 不等于一定 memory-bound；bound 看 AI 与 ridge，优化程度看离 roof 的距离。
