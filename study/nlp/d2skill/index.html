    Dynamic Dual-Granularity Skill Bank for Agentic RL (D2Skill)

    论文信息：Songjun Tu, Chengdong Xu, Qichao Zhang, Yaocheng Zhang, Xiangyuan Lan, Linjing Li, Dong Li, Dongbin Zhao（中科院自动化所 / 鹏城实验室 / 中山大学 / MemoraX AI）， arXiv:2603.28716v2 (2026.05)。 论文原文 代码 提出 D2Skill——动态双粒度技能库，用"任务技能 + 步骤技能"两层粒度复用经验， 并在训练中通过配对 rollout 估计技能效用、动态检索与剪枝，让技能库与策略协同进化。

    图片占位符：论文 Figure 1，D2Skill 框架总览（(a) 检索-反思生成-管理的双粒度 技能库闭环，(b) ALFWorld / WebShop 主要结果）。

    1. 摘要 (Abstract)

    • 核心问题：Agentic RL 能从可复用经验中获益，但现有技能方法大多聚焦轨迹级 引导，缺乏对"持续演化的技能记忆"进行有原则的评估与维护。
    • 提出方案 (D2Skill)：将可复用经验组织为两层——
    • 任务技能 (Task Skills)：高层规划与探索的全局引导。
    • 步骤技能 (Step Skills)：细粒度决策支持与局部错误修正。
    • 配对 rollout 联合训练：同一策略下同时跑"基线组"与"技能注入组"轨迹， 用两者的性能差距推导事后效用信号 (Hindsight Utility Signal)，同时服务于 技能更新与策略优化。
    • 技能库演化：完全基于训练期经验构建，通过反思 (Reflection) 持续扩充， 并通过效用感知的检索与剪枝 (Utility-Aware Retrieval & Pruning) 维护。
    • 效果：在 ALFWorld、WebShop、Search-Augmented QA 上，跨不同规模模型显著 优于无技能基线；消融证实双粒度建模与动态维护是关键，且技能具备跨评估设置 的迁移性，训练开销增加很小。

    2. 引言 (Introduction)

    • 背景：Agentic RL 通过文本接口在长时程决策任务（交互环境、网页搜索、科研场景） 上训练语言智能体，问题严重部分可观测，长时程上信用分配困难。在稀疏奖励与大动作 空间下，学习需要可跨任务迁移的可复用知识。
    • 现有方案的不足（两条线）：
    • 轨迹级反思的局限：很多方法从完整轨迹提炼技能、强调任务级反思，能提供高层 引导，却难以修正单个交互步骤上的细粒度错误（如某个局部动作选择失误）。
    • 技能库无限膨胀：随训练推进技能库持续增长，检索对冗余与技能质量越来越敏感； 若缺乏有原则的技能评估与剪枝，无效/冗余技能会污染检索结果、阻碍策略优化。
    • D2Skill 的定位：在训练全程维护"任务 + 步骤"双粒度技能；对比同一策略下 技能注入与未注入的 rollout，估计技能的事后效用，用于检索、维护与策略优化。
    • 三大贡献：
    • 提出 D2Skill——动态双粒度技能库框架，将可复用经验组织为任务技能（高层引导）
      • 步骤技能（局部交互支持）。
    • 提出联合训练范式：策略与技能库协同进化，技能经反思扩充、以效用感知的 检索与剪枝维护，训练全程更高效地使用记忆。
    • 在 ALFWorld、WebShop、Search-Augmented QA 上评估（Qwen2.5-7B-Instruct 与 Qwen3-4B-Instruct），一致优于无技能基线，消融验证核心设计。

    3. 动机 (Motivation)

    3.1 局部错误需要细粒度技能

    • 任务级技能主要提供全局引导，但长时程交互中的很多失败发生在整体规划已合理之后 的局部错误：智能体到达具体决策点时，必须根据当前观测即时反应，而非只依赖轨迹级计划。
    • 例子（Figure 2）：任务技能能正确描述"冷藏物体并放到目标位置"的高层流程，但当打开 一个看似合理的容器却发现是空的后，它无法告诉智能体如何恢复——此时缺的是一条简短的 局部修正规则，如"换到另一个可能的位置搜索，而不是重复同一失败的搜索"。
    • 两层粒度恰好对应 Agentic RL 的两类主导失败模式：全局规划 (Global Planning) 与局部恢复 (Local Recovery)。

    图片占位符：论文 Figure 2，步骤技能修正局部搜索失败——无步骤技能时智能体在负面 观测后重复同一失败搜索，有步骤技能则被引导切换到另一个可能位置。

    3.2 增长中的技能库受益于动态管理

    • 静态复用的问题是：训练中记忆不断增长，但并非所有生成的技能同样有用——有的过度 特化于单个失败，有的随后续更强技能出现而冗余，有的空占检索与 prompt 预算。
    • 这一局限在 SkillRL 等方法中尤其明显：它们检索存储记忆，却不显式估计其效用， 因此"攒更多技能"并不保证更好的引导。
    • 观察（Figure 3）：检索到的技能可带来可测收益，而效用感知的管理能让高质量技能 长期保留 → 动机是动态技能管理：不把库当作静态记忆，而是按估计效用显式 排序、保留、剪枝。

    图片占位符：论文 Figure 3，(a) ALFWorld 训练成功率曲线（D2Skill 技能组 vs 配对基线组 vs GRPO）；(b) 有无管理的技能库效用动态对比。

    4. 方法论 (Method) —— 核心章节

    4.1 总体框架 (Overview)

    框架由三部分紧密耦合（Figure 4）：

    1. 带技能注入的 RL 训练：每个训练组含"基线组"与"技能注入组"两条配对 rollout （同一策略），其性能差距为策略优化与技能效用估计提供事后信号（§4.2）。
    2. 反思驱动的技能生成：当表现不佳时，反思模块把代表性轨迹归纳为可复用的 任务技能与步骤技能，规范化后加入技能库。
    3. 技能检索与库管理：交互时从库中检索相关技能注入策略上下文；技能效用在线更新， 定期剪枝以保持紧凑有效的记忆（§4.3）。

    图片占位符：论文 Figure 4，D2Skill 总体框架——每个任务下 rollout 分为基线组与 技能组，性能差距产生事后信号；对失败轨迹反思产出任务/步骤技能；技能带检索键存储、 交互中复用、按效用定期剪枝。

    4.2 带技能注入的 RL 训练与事后优化 (Hindsight Optimization)

    • 配对 rollout：对每个任务 \(g\) 采样一组 \(N\) 条并行轨迹 \(G_g\)，均分为技能组 \(G^{\text{skill}}_g\) 与基线组 \(G^{\text{base}}_g\)（各 \(N/2\) 条）。技能组交互时检索 技能库，基线组同策略但不注入技能。\(Y_i\in\{0,1\}\) 为轨迹 \(i\) 的终止成功指示。 记组内成功率 \(\bar Y^{\text{base}}_g\)、\(\bar Y^{\text{skill}}_g\)。
    • 事后信号与效用更新：用两组成功率差构造事后信号—— [ \Delta^{\text{task}}_g = \bar Y^{\text{skill}}_g - \bar Y^{\text{base}}_g,\qquad c_i = Y_i - \bar Y^{\text{base}}_g . ]
    • \(\Delta^{\text{task}}_g\)：任务级事后信号，整组任务上下文相同，故所有被检索的 任务技能共享同一信号。
    • \(c_i\)：轨迹级信用，用于该技能注入轨迹上检索到的步骤技能。
    • 每个技能 \(m\) 维护效用 \(u_m\)，以指数滑动平均更新： [ u_m \leftarrow (1-\beta_{\text{task}})u_m + \beta_{\text{task}}\Delta^{\text{task}}g, \qquad u_m \leftarrow (1-\betac_i . ]}})u_m + \beta_{\text{step}
    • 事后内在奖励塑形 (Hindsight Intrinsic Reward)：鼓励有效使用检索技能， 对技能注入轨迹 \(i\in G^{\text{skill}}_g\)： [ R^{\text{int}}_i = \lambda\,(Y_i - \bar Y^{\text{base}}_g), ] 衡量相对基线的性能增益，在技能注入轨迹末尾加入并参与策略优化。
    • 策略优化：技能组轨迹回报加上 \(R^{\text{int}}\) 后，在整组上做组归一化求优势： [ \tilde R_i = \begin{cases} R_i + R^{\text{int}}_i, & i\in G^{\text{skill}}_g\ R_i, & i\in G^{\text{base}}_g \end{cases}, \qquad A_i = \frac{\tilde R_i - \text{mean}({\tilde R_j})}{\text{std}({\tilde R_j})}. ] 用 GRPO 风格裁剪目标在"事后增强优势"上优化策略。

    4.3 技能生成、检索与库管理

    • 反思与技能生成：仅当任务组性能差（\(\bar Y^{\text{skill}}_g < \tau_{\text{ref}}\)）时 触发。从技能组采样一条失败轨迹 \(\tau^-_g\)，若可得再从任一组取一条成功轨迹 \(\tau^+_g\)，反思器每任务组最多产出一条任务技能与一条步骤技能： [ m^{\text{task}}_g = f{\text{task}}_{\text{reflect}}(g,\tau-_g,\tau^+_g),\qquad (m^{\text{step}}_g, o_j) = f{\text{step}}_{\text{reflect}}(g,\tau-_g,\tau^+_g), ] 其中 \(o_j\) 为失败轨迹上最早失败步骤的观测。
    • 检索键 (Retrieval Key)：任务技能 \(k_m = g\)；步骤技能 \(k_m=(g,o_j)\)。 新技能去重后插入技能库，参与后续检索与效用更新。
    • 两阶段检索 (Two-Stage Retrieval)：
    • 候选召回：从池 \(M\in\{M^{\text{task}}, M^{\text{step}}\}\) 中按查询键 \(q\) 与 \(k_m\) 嵌入的余弦相似度召回 top-\(m\) 候选，并施加最小相似度阈值 \(\tau_{\text{sim}}\) （只保留 \(\text{sim}(q,k_m)\ge\tau_{\text{sim}}\)）。
    • 效用感知排序：结合语义相似度与"基于效用的探索"打分： [ \text{score}(m) = \alpha\,d_{\text{sim}}(m,q) + (1-\alpha)\left(u_m + \eta\sqrt{\frac{\log(1+N_r)}{1+n_m}}\right), ] 其中 \(n_m\) 为技能已检索次数，\(N_r\) 为活跃池总检索次数；第二项是 UCB 式奖励， 鼓励探索检索次数少的技能。按 score 排序取 top-\(k\)（\(k<m\)）注入策略上下文。
    • 按效用剪枝 (Utility-Based Pruning)：防止技能库无界增长，周期性剪枝每个池； 每池有容量上限 \(N_{\max}\)。当 \(|M|>N_{\max}\) 时，按驱逐分 [ \text{evict}(m) = u_m + \eta\sqrt{\frac{\log(1+N_r)}{1+n_m}}, ] 升序排序，移除得分最低者直至 \(|M|\le N_{\max}\)。最近 \(T_{\text{prot}}\) 训练步内 新建的技能不参与驱逐（保护窗口），保证其得到充分评估。

    5. 实验 (Experiments)

    5.1 设置 (Settings)

    • 基准与协议：ALFWorld、WebShop（交互式），Search-Augmented QA（搜索增强 QA）。 交互式基准训练 160 步、每 5 步在 128 个验证任务上评估；Search-Augmented QA 训练 200 步按最终测试集性能报告。验证时技能库冻结（只检索、不反思不更新）。
    • 模型：Qwen2.5-7B-Instruct（SFT 初始化，同 SkillRL）与 Qwen3-4B-Instruct-2507。 反思器用外部 LLM（Gemini-3-Flash 或 O3），Self 设置下用开放模型自生成技能。
    • 超参：组大小 \(N=8\)（技能/基线各半），相似度阈值 \(\tau_{\text{sim}}=0.7\)， α=0.1，注入技能 ALFWorld 任务/步骤各 top-3，WebShop 各 1，反射阈值 \(\tau_{\text{ref}}=0.5\)， 容量上限各 300，保护窗口 \(T_{\text{prot}}=10\)。
    • 基线：
    • 交互式：Origin（无 RL）、GRPO（无技能）、Mem0+GRPO / SimpleMem+GRPO（外部记忆）、 SkillRL（最相关的技能库先验）。
    • QA：Search-R1、ZeroSearch、StepSearch、EvolveR、Dr.Zero、SkillRL(O3)。

    5.2 主要结果 (Main Results)

    ALFWorld / WebShop（Table 1，Qwen2.5-7B-Instruct）：

    • D2Skill 最强变体在 ALFWorld 上整体成功率达 90.6，WebShop 达 84.4。
    • 对比：Origin 12.5 / 3.9，GRPO 75.0 / 72.6，SkillRL(O3) 89.1 / 72.7。

    Qwen3-4B-Instruct-2507：

    • ALFWorld 整体成功率从 GRPO 的 53.9 提升到 72.7；WebShop 上仍强于 GRPO。

    Search-Augmented QA（Table 2，Qwen2.5-7B）：

    • 平均准确率 44.9（D2Skill(O3)），优于 Search-R1 38.6、SkillRL(O3) 43.1；
    • 在 multi-hop QA（HotpotQA 47.5、2Wiki 43.7）上增益尤其明显——与步骤技能的角色 一致：多跳搜索需要一串局部正确的决策。Qwen3-4B 上由 Search-R1 的 36.0 提升到 42.8。

    Self 设置（无闭源反思器）：

    • 仅靠自反馈仍优于 GRPO：ALFWorld 82.8、WebShop 81.3（Qwen2.5-7B）——核心增益不依赖 特权闭源监督，但更强外部反思器仍能进一步提升轨迹诊断与技能抽象质量。

    强初始化（SFT teacher）设置：

    • 仅 40 训练步即达 ALFWorld 92.2，接近 GRPO 训练 120 步；120 步后提升至 95.3， 训练效率与最终性能均优于同预算 GRPO。WebShop 趋势一致。

    图片占位符：论文 Table 1 / Table 2，ALFWorld 与 WebShop 各子任务成功率、 WebShop 分数，及 Search-Augmented QA 单跳/多跳准确率对比。

    w/o 步骤技能 57.8 55.8 60.2

    • 技能管理最关键：去掉剪枝维护带来最大下降 → 动态库维护（丢弃无效技能、 保留紧凑高效用知识）是核心增益来源。

    5.4 分析 (Analysis)

    • 技能库效用与迁移性：
    • 启用管理后，技能库与被检索技能的平均效用持续更高（过滤无效技能）。
    • 技能可迁移：评估时即使移除技能库，D2Skill 训练出的策略仍与 GRPO 相当甚至更优 → 部分增益在训练中被内化进策略；评估时换用 Gemini-3-Flash 生成的技能库仍有效， 自生成技能库最有效 → 学到的是可复用技能而非绑定特定库。
    • 训练开销：ALFWorld / Qwen3-4B，8×H100 上 D2Skill 25.6 小时，接近 GRPO（20.8h）， 远低于 SkillRL（49.2h），实践中约 1.7× 快于 SkillRL。低开销来自高效检索管线： 批量嵌入查询 + 增量更新技能嵌入（每次库更新只需编码新技能）。

    图片占位符：论文 Figure 5，评估时使用不同技能（D2Skill(O3)/GRPO/无技能）的 成功率对比；Figure 6，验证成功率随训练墙钟时间的变化（D2Skill 约 1.7× 快于 SkillRL）。

    6. 相关工作 (Related Work)

    • 带记忆的智能体演化 (Agent Evolution with Memory)：通过外部记忆与可复用经验使 LLM 智能体超越参数更新。D2Skill 追随此方向，但聚焦 RL 期技能估值与维护——通过 配对技能/基线 rollout 为技能打分，而非仅积累文本记忆。
    • 记忆增强的 Agentic RL (Memory-Augmented Agentic RL)：把外部记忆当作策略优化的 非参数补充。D2Skill 与该线最接近，但两点差异：
    • 联合建模任务级 + 步骤级技能（而 SkillRL 的"两类任务"只是任务分类， 引导仍是任务级、每任务只检索一次）。
    • 训练中动态估值、更新与剪枝技能，而非把库当作近似静态记忆；技能生成与 管理发生在训练期，不依赖特权验证信息。

    7. 结论 (Conclusion) 与局限

    • D2Skill 在一个联合训练循环内整合任务级引导、步骤级修正与效用感知技能管理， 在交互式基准与搜索增强 QA 上一致优于强基线，消融与分析确认双粒度建模与动态 库维护的关键作用。
    • 局限 (Limitations)：
    • 技能构建敏感性：技能质量仍依赖反思与初始化所用的监督来源，弱监督/全自生成 下的稳定性待改进。
    • 基准范围有限：三个基准尚未覆盖开放世界环境的多样性与噪声。
    • 技能质量与检索鲁棒性：更复杂环境下，噪声、过度特化或过时技能仍可能影响 检索质量与记忆管理。
    • 展望：扩展到更广的 Agentic 领域，并减少对外部反思模型的依赖。

    8. 一句话总结

    D2Skill 用"任务技能 + 步骤技能"双粒度技能库，配合配对 rollout 的事后效用信号、 反思生成与效用感知的检索/剪枝，让策略与技能库协同进化——关键洞察是：**技能不仅 要"被积累"，还要在训练中被估值、被管理（Why > What），局部修正与全局规划同样重要。
